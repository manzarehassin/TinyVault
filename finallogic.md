# TinyVault: Ultra-Secure SPI Slave Firmware Architecture & Protocol Specification

**Target MCU:** Microchip ATtiny13A (8-pin SOIC/DIP)  
**Clock Configuration:** 1.2 MHz nominal CPU clock (`CKDIV8` enabled, `F_CPU = 1200000UL`)  
**Recommended Safe SPI Clock Speed:** $\le 300\text{ kHz}$ (Bit-banged or hardware master clock, maintaining at least a $4\times$ safety margin relative to the 1.2 MHz CPU clock to prevent timing drift under low-voltage CR2032 conditions).  
**Power Profile:** Optimized for CR2032 coin cell safety down to 1.8V. Peripherals (ADC, Analog Comparator, Timer0) are permanently disabled by default for maximum power conservation.  
**Version:** 4.4  

---

## 1. Hardware Pinout & Wake-Up Mechanism

The ATtiny13A provides 6 usable I/O pins (PB0–PB5) alongside VCC and GND. TinyVault assigns these pins as follows:

| Pin Number | Pin Name | Default Function | Alternative / Dual Mode Function | Description |
| :---: | :---: | :--- | :--- | :--- |
| **1** | `PB5` | `RESET` | High-Voltage Programming / External Reset | System reset line. |
| **2** | `PB3` | **Freed GPIO** | Analog Input (when ADC is ON) / Floating Digital Input (when ADC is OFF) | Flexible hybrid pin controlled via `FLAG0.bit4`. |
| **3** | `PB4` | `CS` | Chip Select & **Wake-Up Pin** (`PCINT4`) | Active-LOW hardware framing boundary and falling-edge wake-up interrupt source. |
| **4** | `GND` | `GND` | System Ground | Battery and circuit common ground. |
| **5** | `PB0` | `MOSI` | Master Out Slave In | SPI Data Input line. |
| **6** | `PB1` | `MISO` | Master In Slave Out | SPI Data Output line. |
| **7** | `PB2` | `SCK` | Serial Clock | SPI Clock Input line generated by the Master. |
| **8** | `VCC` | `VCC` | Power Supply (1.8V – 3.0V) | Connected to CR2032 coin cell and local decoupling caps. |

### Wake-Up Execution Flow
1. **Pin Change Interrupt (`PCINT4`):** In deep power-down sleep, the ATtiny13A enables a Pin Change Interrupt on pin `PB4` (`CS`).
2. **Falling Edge Trigger:** When the master pulls `CS` **LOW** to initiate an SPI frame, the falling edge immediately triggers `PCINT4` and wakes the CPU from deep sleep.
3. **SPI Ready State:** The CPU resumes execution instantly to process incoming `SCK` clock pulses and deserialize the command frame.
4. **Auto-Sleep Return:** When the transaction concludes and `CS` transitions **HIGH**, the auto-sleep governor evaluates pending jobs and puts the MCU back into deep power-down sleep.

## 2. System Memory Map & Default Values

TinyVault implements a unified memory map combining volatile user RAM, RAM-mapped status/control registers, and non-volatile EEPROM storage.

### RAM & Register Space (Addresses 0–35)
* **Addresses 0–31 (`0x00`–`0x1F`):** User RAM (General-purpose volatile storage). *Default: `0x00`*
* **Address 32 (`0x20`):** `FLAG0` (Control & Status Register). *Default: `0x00`*
* **Address 33 (`0x21`):** `FLAG1` (Status, Address & ADC Data Register). *Default: `0x00`*
* **Address 34 (`0x22`):** `FLAG2` (Dynamic Payload & Result Storage). *Default: `0x00`*
* **Address 35 (`0x23`):** GPIO Digital Read Slot (RAM-mapped address for reading the dual-mode pin digitally). *Default: Live Pin State*

### Non-Volatile EEPROM / ROM Space (Addresses 0–63)
* **Addresses 0–62 (`0x00`–`0x3E`):** User EEPROM / ROM storage. *Default: `0xFF` / `0x00`*
* **Address 63 (`0x3F`):** Private system metadata. *Strictly protected from SPI writes.*

## 3. SPI Communication Protocol & Command Architecture

TinyVault utilizes a bit-banged SPI Mode 0 protocol featuring a precise **2-bit opcode + 6-bit address/modifier** framing structure (`[opcode 2 bits][address 6 bits]`).

### Complete SPI Command Map
* **RAM & Register Reads (`Opcode: 00` -> `0b00xxxxxx`)**
  * **General RAM Read:** `0b00xxxxxx` (Addresses 0–31)
  * **`FLAG0` Read:** `0b00100000` (Address 32 / `0x20`)
  * **`FLAG1` Read:** `0b00100001` (Address 33 / `0x21`)
  * **`FLAG2` Read:** `0b00100010` (Address 34 / `0x22`)
  * **GPIO Digital Read:** `0b00100011` (Address 35 / `0x23`)

* **RAM & Register Writes (`Opcode: 01` -> `0b01xxxxxx 0byyyyyyyy`)**
  * **General RAM Write:** `0b01xxxxxx 0byyyyyyyy` (Addresses 0–31)
  * **`FLAG0` Write:** `0b01100000 0byyyyyyyy` (Address 32 / `0x20`)
  * **`FLAG1` Write:** *Strictly Forbidden / Blocked via SPI*
  * **`FLAG2` Write:** *Strictly Forbidden / Blocked via SPI*

* **ROM (EEPROM) Operations (`Opcode: 10 & 11`)**
  * **ROM Read:** `0b10xxxxxx` (Addresses 0–63, subject to safety locks)
  * **ROM Write:** `0b11xxxxxx 0byyyyyyyy` (Addresses 0–62 only; Address 63 blocked; deferred until `CS` goes HIGH)

## 4. Flag Register Specifications & Bit Layouts

### ⚙️ `FLAG0` Register (Control & Status - Address 32) [Default: `0x00`]
* **Bit 7 (`BUSY`):** Busy State / Engine Status. Active when processing background tasks. If `1`, any incoming SPI request is immediately intercepted, shifts out the standard error code **`0xAA` (`10101010`)**, and the transaction is rejected.
* **Bit 6 (`ROM_RO`):** ROM Read-Only protection state. Enforces write protection for user EEPROM addresses 0–62.
* **Bit 5 (`RAM_RO`):** RAM Read-Only protection state. Enforces write protection for user RAM addresses 0–31.
* **Bit 4 (`ADC_CTRL`):** Manual ADC Control Switch & Sleep Governor.
  * `0` = **ADC OFF** (Default): Power-saving mode enabled; permits automatic deep sleep when `CS` goes HIGH and no EEPROM writes are pending.
  * `1` = **ADC ON**: Explicitly turns on the ADC for on-demand sampling, disables automatic sleep, and keeps the MCU awake.
* **Bits 3–1 (`SIG`):** 3-bit Device Signature (readable and writable via SPI).
* **Bit 0 (`PENDING`):** EEPROM Pending Write Flag. When set (`1`), it locks out the ADC from modifying flags and blocks further EEPROM read/write requests until committed.

### 🗂️ `FLAG1` Register (Status, Address & ADC Data - Address 33) [Default: `0x00`]
* **Bit 7:** EEPROM write skip status (Read-only via SPI).
* **Bit 6:** Verification success state (Read-only via SPI).
* **Bits 5–2:** Target EEPROM address storage (Valid for user ROM addresses 0–62).
* **Bits 1–0:** ADC Result Bits (Stores lower/extended conversion bits when the ADC is ON and no EEPROM write is pending).

### 📦 `FLAG2` Register (Dynamic Payload & Result Storage - Address 34) [Default: `0x00`]
* **Bits 7–0:** Dynamic data container whose ownership strictly shifts depending on the system state:
  1. **Pending EEPROM Write Payload:** Holds the data waiting to be committed to ROM. While a write is pending, `FLAG2` is locked and protected from all interference.
  2. **Live ADC Result:** Holds active analog conversion data when the ADC is ON (`FLAG0.bit4 = 1`) and no EEPROM write is pending. When active, incoming SPI read commands are blocked from overwriting `FLAG2`.
  3. **SPI EEPROM Read Result:** Holds the byte fetched from an explicit SPI ROM read request when no writes or active ADC sessions interfere. Internal background reads never modify `FLAG2`.

---

## 5. EEPROM Deferred Write & Verification Lifecycle

1. **In-Frame Buffering (`CS` LOW):** During active SPI communication, incoming ROM write commands are **not** written physically. The target address is stored in `FLAG1`, the payload byte is buffered into `FLAG2`, and `FLAG0.bit0` (`PENDING`) is set.
2. **Deferred Execution Post-`CS`:** The actual physical EEPROM programming executes strictly **after** `CS` goes HIGH:
   * **Pre-Write Internal Read:** Inspects the target address. If the stored value already matches the payload, the physical write is skipped to prevent unnecessary wear (updating `FLAG1` write skip status). *Note: Internal reads never modify `FLAG2`.*
   * **Conditional Physical Write:** If values differ, the byte is written.
   * **Post-Write Verification Read:** Verifies success, updating `FLAG1` verification state. *Note: Internal verification reads never modify `FLAG2`.*
   * **Cleanup:** Once completed, `FLAG2` is cleared (`0x00`), and `FLAG0.bit0` is reset to `0`.
3. **Power-Fail Battery Safety:** Without a dedicated power monitor pin, if power drops during or right after a session, any pending write executes using available battery/decoupling power before entering deep sleep.

## 6. Dual-Mode GPIO Pin & On-Demand ADC Architecture

The freed GPIO pin (`PB3`) functions as a flexible hybrid input governed by `FLAG0.bit4`:

* **When ADC is ON (`FLAG0.bit4 = 1`):**
  * The pin acts as an analog input channel.
  * Active conversion results populate `FLAG1` (bits 1–0) and `FLAG2`.
  * SPI read commands are blocked from overwriting `FLAG2`, allowing the master to safely poll live sensor data.
  * *Safety Catch:* If an EEPROM write is pending (`FLAG0.bit0 == 1`), the ADC is strictly locked out from modifying any flags or `FLAG2`.
* **When ADC is OFF (`FLAG0.bit4 = 0`):**
  * Analog circuitry is disabled for maximum power savings.
  * The pin becomes accessible via the **SPI Digital Read command** (`0b00100011` / Address 35).
  * The firmware configures the pin data direction register (`DDRB`) as a floating input and samples its real-time digital logic level (`HIGH`/`LOW`), returning it over the SPI bus.

---

## 7. Error Handling, Resiliency & Auto-Sleep Logic

* **Busy Rejection (`0xAA` Error Code):** If the slave is busy (`FLAG0.bit7 == 1`), any incoming request immediately shifts out `10101010` (`0xAA`) and aborts the transaction.
* **Timing Mismatch & Framing Safeguards:** `CS` acts as the absolute hardware framing boundary. If clock pulses are missed, timing drifts, or bit desynchronization occurs, pulling `CS` HIGH instantly forces the slave's SPI state machine to abort, clear internal bit counters, and discard corrupted shift-register data.
* **Automatic Sleep Routine:** The moment `CS` goes HIGH, the slave checks for pending jobs (`FLAG0.bit0 == 1`). If no jobs are pending and `FLAG0.bit4` is `0`, the ATtiny13A automatically executes its deep power-down sleep instruction (`sleep_cpu()`), dropping current draw to micro-amps to protect the CR2032 coin cell.
